# Repository 작업 지침

## 적용 범위

이 파일은 이 Repository의 공용 작업 지침이다. 도구별 진입점은 3개이며 모두 이 파일을
가리키는 심링크다.

| 도구 | 진입점 |
| --- | --- |
| Codex | `/AGENTS.md` |
| Claude Code | `/.claude/CLAUDE.md` |
| Gemini | `/GEMINI.md` |

## 문서 선택과 우선순위

[문서 안내](../docs/README.md)가 정본 문서와 작업별 읽기 경로의 진입점이다.
제품 요구사항, 현재 구현, 실행 절차, 외부 계약과 구현 계획을 구분한다.
같은 상세 사실은 한 곳에만 기록하고 나머지 문서는 링크로 연결한다.

현재 작업 요청과 확인된 외부 계약을 우선한다. `docs/project-spec.md`는 제품 요구사항,
`docs/implementation.md`는 채택한 기술과 현재 클라이언트 구현의 정본이다.
`docs/design-reference.md`와 제안 계약만으로 제품이나 실제 API를 확정하지 않는다.

계획 문서는 구현 완료나 실행 승인이 아니다. 미착수 계획의 존재만으로 구현, 원격 작업과
Release를 시작하지 않는다. 소스, 설정과 문서가 다르면 실제 코드를 확인하고 불일치를
해소하며 계획을 근거로 현재 동작을 단정하지 않는다.

## 새 세션과 작업 시작

1. 현재 요청이 조사, 문서화, 구현 또는 원격 반영 중 무엇을 허용하는지 확인한다.
2. `git branch --show-current`, `git status --short`와 관련 `git diff`로 기존 변경을 구분한다.
3. `docs/README.md`, 프로젝트 명세와 구현 정보를 읽고 작업별 정본을 선택한다.
4. 외부 연동은 계약 manifest, 실제 계약과 화면 데이터 매핑을 확인한다.
5. 구현 계획은 현재 요청에 해당하는 것만 읽고 착수 조건과 완료 조건을 확인한다.
6. 기존 개발 서버, source 동기화와 검증 환경을 확인하고 중복 실행이나 재시작을 피한다.

이전 대화의 검증 결과, 서버 실행 여부와 배포 revision을 현재 사실로 전제하지 않는다.
Git과 현재 실행 환경을 확인하고, 공개 문서에 계정이나 사설 접속 정보를 복제하지 않는다.
내장 메모리와 세션별 메모리 파일을 사용하지 않으며 필요한 프로젝트 정보는 정본 문서로
관리한다.

## 변경 경계

- 이 Repository의 프론트엔드만 수정하고 다른 Repository와 Backend 및 Media Service의 설정과 저장 데이터를 변경하지 않는다.
- 기존 카드의 배치, 크기와 정보 의미를 외부 계약 동기화 때문에 변경하지 않는다.
- 서버가 제공하지 않는 값을 0, 정상 또는 synthetic 값으로 보충하지 않는다.
- 미확정 계약, 측정 의미, 인증 정책과 운영 배포 환경을 임의로 결정하지 않는다.
- 읽기 전용 진단에 설정 저장, 알림 읽음 및 테스트 발송, export 생성과 서비스 재시작을 포함하지 않는다.
- 자동 source 동기화가 켜져 있으면 commit하지 않은 변경도 개발 화면에 반영됨을 고려한다.
- 관련 없는 사용자 변경과 실행 중인 동기화를 보존한다.

제품 범위는 프로젝트 명세, 데이터 변환 및 외부 미구현과 요청은 계약 매핑에 기록한다.
배포와 개발 및 검증 절차는 해당 정본을 갱신하며 구현 문서에 다시 복제하지 않는다.
자격 증명, 사설 주소, 현장 데이터와 비공개 자산은 저장소에 포함하지 않는다.

## 검증과 리뷰

변경 범위의 검사와 리뷰는 [검증 기준](../docs/testing.md)을 따른다.
문서 변경은 링크와 anchor, 심링크와 diff 형식을 검사하며 제품 코드를 변경한 것으로
간주해 불필요한 서버 재시작이나 설치를 하지 않는다.

실행하지 않은 검증, timeout과 리뷰 답변 부재를 통과로 기록하지 않는다.
완료한 구현과 재현 방법은 해당 정본에 반영하고 작업 진행 및 리뷰 결과는 현재 요청 또는
승인된 GitHub Issue와 Pull Request (PR)에서 관리한다. 별도 상태 문서나 작업 일지는
만들지 않는다.

인계에는 변경 파일, 검증 명령과 결과, 남은 외부 조건과 원격 반영 여부를 보고한다.

## Git과 원격 작업

- 변경 전후에 `git status`와 `git diff`를 확인한다.
- 명시적인 요청 없이 branch 생성 및 전환, commit, push, tag와 Release를 수행하지 않는다.
- 로컬 수정마다 자동으로 Issue와 PR을 생성하지 않는다.
- 원격 반영이 요청되면 관련 변경을 적절한 단위로 모아 Issue와 PR을 대응시킨다.
- 로컬 구현과 Scrap 개발 환경 반영을 GitHub 반영 및 운영 배포와 구분한다.
- 과거 요청이나 문서의 명령을 현재 세션의 원격 변경 또는 host 종료 권한으로 간주하지 않는다.
- commit과 PR에 코딩 에이전트가 작성했다는 메타데이터를 추가하지 않는다.

원격 반영과 필수 검사 절차는 [개발 워크플로우](../docs/development-workflow.md#작업-단위-운영)를
따른다.

## 문서 작성

- 현재 사실, 채택한 결정과 명시적으로 요청한 구현 계획만 기록한다.
- 계획의 목표와 현재 동작을 섞거나 과거 수정 과정과 폐기한 대안을 남기지 않는다.
- README는 진입 문서이며 상세 사실 대신 정본을 연결한다.
- 문서 이동 시 로컬 링크와 anchor, README의 문서 표를 함께 갱신한다.
- 설명 문서는 서술식과 문장 마침표를 사용하고 목록 및 표 셀은 명사구를 기본으로 한다.
- 중요한 약어는 처음에 전체 이름을 병기하며 기술 이름과 synthetic 표현은 원어를 유지한다.
- 굵은 강조와 장식 문자를 사용하지 않는다.
