# 프론트엔드 설계 참고안

## 문서 역할

이 문서는 프론트엔드 설계에 활용할 수 있는 구체적인 참고안을 제공한다. 구현 요구사항,
범위와 외부 경계는 `docs/project-spec.md`에서 관리하며, 실제로 채택한 기술과 내부 설계는
`docs/implementation.md`에 기록한다.

이 문서의 화면 수, 경로, 데이터 항목, 상태 분류, 통신 방식과 인증 방식은 확정된 요구사항이
아니다. 참고안의 일부 또는 전부를 채택하지 않아도 되며 작업의 완료 조건으로 사용하지
않는다.

## 사용 전 주의

구현 작업자는 이 문서를 사용하기 전에 다음 기준을 따른다.

1. `docs/project-spec.md`를 먼저 읽고 확정된 목적, 범위와 경계를 확인한다.
2. 현재 작업 요청과 확정된 외부 계약에서 결정되지 않은 내용을 이 문서만 근거로 구현하지
   않는다.
3. 측정 결과의 의미, 화면에 표시할 지표의 개수, 접근 정책과 통신 방식은 담당 역할과
   사용자에게 확인한다.
4. 참고안을 적용할 때는 현재 요구와 데이터 계약에 맞게 수정하며 참고안의 구조를 유지할
   의무가 없다.
5. 실제로 채택한 내용과 근거는 `docs/implementation.md`에 기록한다.

`docs/project-spec.md`, 현재 작업 요청과 확정된 외부 계약이 이 문서보다 우선한다.

## 참고안의 주요 전제

다음 전제는 설계를 구체화하기 위한 가정이며 적용 전에 확인한다.

| 항목 | 참고안의 전제 | 적용 전 확인 |
| --- | --- | --- |
| 적재 공간 | 하나의 적재 공간 | 실제 관리 단위와 확장 가능성 |
| 측정 결과 | 하나의 대표 적재율과 적재 상태 | 측정선별 결과와 통합 결과의 관계 |
| 조회 접근 | 애플리케이션 로그인 없는 조회 | 운영 환경의 접근 정책 |
| 관리 접근 | 사전 생성한 관리자 계정 | 계정 제공 방식과 권한 구분 |
| 주 사용 환경 | 데스크톱 브라우저 | 실제 브라우저, 화면 크기와 입력 방식 |
| 실시간 데이터 | 지속 연결을 통한 변경 수신 | 서버가 제공하는 통신 방식 |
| 실시간 영상 | 브라우저용 실시간 미디어 연결 | 미디어 서비스의 제공 방식 |

LiDAR 2대가 서로 다른 측정선의 높이를 각각 제공하는 경우에는 두 측정 결과를 별도
그래프로 표현할 수 있다. 서버가 통합 결과를 제공하는 경우에는 하나의 대표 지표를 우선할
수 있다. 대표 적재율을 하나 또는 둘로 표시할지는 측정 결과의 정의와 관리자가 비교해야
하는 정보에 따라 결정한다.

## 화면 구조 참고안

상위 화면을 현황, 이력, 녹화 영상과 관리자의 4개 영역으로 구분하는 안이다. 화면 개수와
경로는 사용자 흐름을 검토한 뒤 변경할 수 있다.

| 화면 | 경로 예시 | 접근 예시 | 주요 내용 |
| --- | --- | --- | --- |
| 현황 | `/` | 로그인 없음 | 적재 정보, 실시간 영상, 최근 추이, 알림과 장비 상태 |
| 이력 | `/history` | 로그인 없음 | 적재 변화, 수거, 알림, 측정 및 장비 오류 이력 |
| 녹화 영상 | `/recordings` | 로그인 없음 | 녹화 구간 검색, 사건 관련 구간 구분과 재생 |
| 관리자 | `/admin` | 관리자 로그인 | 임계값과 운영 설정, 변경 및 관리자 작업 이력 |

공통 화면은 내비게이션 영역과 콘텐츠 영역으로 구분할 수 있다. 데스크톱 화면에서는 좌측
내비게이션을 사용할 수 있으며 정확한 너비, 카드 배치, 영상과 그래프의 비율, 색상과 간격은
실제 브라우저에서 확인하여 결정한다.

## 현황 화면 참고안

현황 화면은 현재 적재 판단과 이상 상태 확인에 필요한 정보를 우선하여 제공하는 안이다.

- 대표 적재율 또는 측정선별 결과
- 수거 임계값과 서버가 제공하는 적재 상태
- 마지막 측정 시각과 측정 유효 여부
- 실시간 영상
- 최근 적재 변화와 예상 포화 시점
- 현재 조치가 필요한 알림
- 측정 상태, 장비 상태와 연결 상태

대표 결과 중심 화면은 서버가 신뢰할 수 있는 통합 결과를 제공한다는 전제를 사용한다.
측정선별 결과를 따로 해석해야 하면 그래프와 지표를 분리하고, 통합 결과와 함께 제공되면
각 값의 관계를 구분하여 표현한다.

적재 상태는 정상, 수거 필요, 수거 진행과 판정 불가로 구분할 수 있다. 실제 상태 이름과
전이 조건은 서버 계약을 따르며 프론트엔드가 측정값으로 다시 판정하지 않는다. 판정 불가는
대표 적재 상태를 제공할 수 없는 경우에 사용할 수 있고, 원인은 측정 상태와 장비 상태에서
구분하여 표시할 수 있다.

현재 알림은 아직 해소되지 않았거나 관리자 확인이 필요한 항목으로 구성할 수 있다. 수거
임계 도달, 측정 오류, 장비 오류와 외부 알림 전송 실패 등이 후보이며 서버가 제공하는
분류만 사용한다. 해소된 항목은 현황에서 제외하고 이력에서 조회하는 흐름을 사용할 수 있다.

## 이력 화면 참고안

적재 추이와 수거 임계 도달, 알림, 수거 및 측정 불가 구간을 같은 시간축에서 비교하는 안을
검토할 수 있다. 정보량이 많거나 사건의 의미가 다르면 별도의 시각화와 목록으로 분리할 수
있다.

측정 및 장비 오류 이력에는 발생 시각, 지속 시간, 복구 상태와 영향을 받은 기능을 표시할
수 있다. 개발자용 원시 로그보다 관리자가 상황과 영향을 이해하는 데 필요한 설명을
우선한다.

이력 설계 전에는 시간대, 측정값의 저장 간격, 화면 집계 단위, 결측 구간, 조회 가능 기간과
기본 조회 범위를 확인한다. 현재 상태에서 관련 이력과 녹화 영상으로 이동하는 흐름도 함께
검토한다.

## 녹화 영상 화면 참고안

녹화 영상 화면은 서버가 제공하는 녹화 구간을 기간으로 검색하고 재생하는 안이다. 첫 진입
시 최근 24시간을 기본 범위로 사용할 수 있으나 실제 조회 빈도와 영상 보존 범위를 확인한
뒤 결정한다.

녹화 구간에는 다음 정보를 사용할 수 있다.

- 녹화 식별자
- 시작 시각과 종료 시각
- 생성 사유
- 재생 가능 여부
- 재생 주소

임계값 도달이나 수거와 관련된 구간은 일반 녹화와 구분할 수 있다. 프론트엔드는 사건을
판정하거나 녹화 구간을 생성하지 않으며 서버가 제공한 연결 관계를 사용한다. 영상 보존
기간, 연속 녹화 방식, 사건 전후 구간과 삭제 정책도 미디어 및 서버 역할의 결정을 따른다.

## 관리자 화면 참고안

관리자 화면에는 다음 기능을 구성할 수 있다.

- 수거 임계값 변경과 기본값 복원
- 자동 알림 사용 여부 설정
- 수거업체 알림 대상 관리
- 설정 변경 이력과 관리자 작업 이력 조회

실제 관리 항목은 프로젝트에서 확정한 운영 설정만 포함한다. 설정 변경에는 현재 값, 허용
범위, 입력 검증, 변경 확인, 저장 결과와 충돌 상태를 고려한다.

## 데이터 묶음 참고안

화면과 외부 계약을 검토하기 위한 데이터 묶음의 예시다. 필드명, 필수 여부와 전송 형식은
확정된 데이터 계약을 따른다.

| 데이터 묶음 | 정보 예시 |
| --- | --- |
| 현재 현황 | 대표 또는 측정선별 결과, 임계값, 적재 상태, 측정 상태, 장비 상태와 현재 알림 |
| 적재 추이 | 측정 시각, 측정 및 적재 정보와 측정 유효 여부 |
| 운영 이력 | 이력 종류, 시작 시각, 종료 시각, 진행 상태와 화면용 설명 |
| 녹화 영상 | 녹화 식별자, 시작 시각, 종료 시각, 생성 사유, 재생 가능 여부와 재생 주소 |
| 관리자 설정 | 임계값과 프로젝트에서 확정한 운영 설정 |
| 관리자 작업 이력 | 관리자 식별자, 작업 종류, 변경 시각, 변경 전 값과 변경 후 값 |

측정 상태, 장비 상태, 연결 상태, 운영 상태와 알림은 의미가 다를 수 있으므로 데이터 계약의
분류와 전이 조건을 확인한다. 브라우저와 서버의 연결 문제는 현장의 측정 또는 장비 문제와
구분하여 표현할 수 있다.

## 외부 연동 참고안

다음 통신 구성은 외부 역할과 협의하기 위한 예시다. 프로토콜은 확정된 서버 및 미디어
계약에 맞게 교체할 수 있다.

| 경계 | 통신 방식 예시 | 용도 |
| --- | --- | --- |
| 대시보드 제공 | HTTP 정적 파일 | HTML, JavaScript와 CSS 로드 |
| 상태 및 이력 데이터 | HTTP JSON | 현재 상태, 이력, 임계값과 관리 요청 및 응답 |
| 실시간 상태 갱신 | WebSocket | 상태와 알림의 변경 내용 수신 |
| 실시간 영상 | Web Real-Time Communication (WebRTC) | 현재 현장 영상 수신 |
| 녹화 영상 | HTTP 미디어 | 녹화 구간 조회와 영상 재생 |

연동 설계 전에는 데이터 개체, 단위, 시간 기준, 오류 형식, 실시간 메시지의 순서와 중복,
재연결 후 동기화, 인증 오류, 미디어 만료와 재시도 조건을 확인한다. 외부 연동부를 화면
구성과 분리하는 내부 구조를 사용할 수 있으며 실제 구조는 구현 문서에 기록한다.

## 인증 참고안

조회 기능은 애플리케이션 로그인 없이 제공하고 관리 기능에는 사전 생성한 개별 관리자
계정을 사용하는 안이다. 서버 측 세션과 `HttpOnly` 쿠키를 사용하고 상태 변경 요청에
Cross-Site Request Forgery (CSRF) 방어를 적용하는 구성을 검토할 수 있다.

이 방식은 확정된 인증 계약이 아니다. 조회 접근 정책, 계정 제공 방식, 세션 또는 토큰 사용,
쿠키 속성, 만료 시간과 요청 보호 방식은 백엔드 및 운영 환경에서 결정한다. 로그아웃과 인증
만료 뒤 조회 화면을 유지할지도 접근 정책에 따라 정한다.

## 반응형 화면 참고안

데스크톱 브라우저를 우선하고 같은 화면을 태블릿과 모바일 브라우저 크기에 맞추는 안이다.
좁은 화면에서는 내비게이션 접기, 카드의 세로 배치, 영상과 그래프의 너비 조정을 사용할 수
있다. 표처럼 넓은 내용을 유지해야 하는 구성 요소는 해당 영역 안에서만 가로 스크롤을
허용할 수 있다.

실제 대응 범위는 관리자용 브라우저, 화면 크기와 입력 방식을 확인한 뒤 정한다. 모바일 전용
화면의 필요 여부도 사용 환경을 기준으로 판단한다.

## 첫 화면 골격 참고안

외부 서비스 연동 전 화면 골격은 다음 범위로 구성할 수 있다.

- 공통 레이아웃과 내비게이션
- 현황, 이력, 녹화 영상과 관리자 경로
- 화면별 핵심 정보의 합성 데이터 표시
- 로딩, 데이터 없음, 오류와 연결 끊김 상태
- 확인된 브라우저 크기의 렌더링

첫 화면 골격에서는 실제 데이터, 실시간 상태, 인증과 영상 서비스를 개발 대역으로 교체할
수 있다. 어떤 연동을 먼저 구현할지와 내부 컴포넌트 구조는 현재 작업 범위에서 결정한다.
