## 상위 컨텍스트

스크랩 모니터링 시스템은 LiDAR 2대, 고정 USB 웹캠, 라즈베리파이 엣지 장비, 모니터링 서버와 관리자 브라우저로 구성한다. 엣지 장비는 LiDAR 데이터를 변환하고 높이를 산출하며 카메라 영상을 서버로 전달한다. 모니터링 서버는 상태 데이터, 이력, 알림, 실시간 영상과 녹화 영상을 관리자 브라우저에 제공한다.

이 저장소는 관리자 브라우저에서 실행되는 대시보드 클라이언트를 구현한다. 센서 원본 데이터 처리, 높이 산출, 서버 영속화와 미디어 서버 구현은 다른 개발 저장소의 책임이다.
정적 산출물을 제공하는 웹 서버, 서비스 라우팅, Transport Layer Security
(TLS), 컨테이너 구성과 운영 배포는 배포 Repository의 책임이다.

LiDAR 2대는 적재 공간의 서로 다른 측정선에서 높이를 산출한다. 두 측정 결과를 결합하는
방식, 대표 높이와 대표 적재율의 정의, 대시보드에 표시할 그래프와 적재율 지표의 개수는
확정되지 않았다. 프론트엔드는 이후 확정되는 측정 결과와 서버 계약을 기준으로 이를
표현한다.

현재 단계에서는 실제 장비를 이용한 입출력과 네트워크 흐름 확인을 우선한다. 현장 검증이나 측정 로직의 시뮬레이션 검증은 현재 구현 범위에 포함하지 않는다.

## 목적

공장 관리자가 브라우저에서 스크랩 적재 상태를 확인하고 수거 판단에 필요한 정보를 사용할 수 있는 대시보드를 제공한다.

## 사용자 기능

대시보드는 다음 사용자 목적을 지원한다.

| 기능 | 목적 |
| --- | --- |
| 현재 모니터링 | 서버가 제공하는 측정 및 적재 정보, 장비 상태, 알림과 실시간 영상 확인 |
| 변화 및 운영 이력 | 시간에 따른 적재 변화와 수거, 알림 및 오류 이력 확인 |
| 녹화 영상 | 조회 가능한 녹화 구간 검색과 재생 |
| 관리 기능 | 수거 임계율과 프로젝트에서 확정한 운영 설정 관리 |

화면 개수와 계층, 적재 정보의 표시 단위, 집계 및 판정 결과의 표현 방식과 시각화 구성은
확정된 현장 구조, 외부 계약과 사용자 요구를 기준으로 구현 과정에서 결정한다. 프론트엔드는
서버가 제공하는 측정, 상태와 예측 결과를 사용하며 높이 산출, 적재율 판정과 예측 로직을
구현하지 않는다.

## 산출물

- 관리자용 웹 대시보드
- 현재 모니터링, 이력, 영상 조회와 관리 기능의 사용자 흐름
- 상태 데이터, 이력, 알림, 실시간 영상과 녹화 영상의 연동 경계
- 실제 연동 전 화면과 사용자 흐름을 검증할 개발 환경

## 범위

### 포함 범위

- 현재 모니터링, 이력, 녹화 영상과 관리 기능
- 조회 및 관리 기능의 접근 제어 흐름
- 실시간 상태, 이력, 알림과 영상 연동
- 로딩, 데이터 없음, 연결 끊김과 오류 상태 표시
- 관리자용 브라우저 환경 대응

### 제외 범위

- LiDAR Software Development Kit (SDK) 연동과 높이 산출
- 카메라 영상 수집, 인코딩과 미디어 서버 구현
- 백엔드 API, 영속 데이터베이스와 서버 저장소 구현
- 웹 서버, TLS, 서비스 라우팅과 전체 시스템 배포 구성
- 실제 현장 데이터 수집과 측정 로직 검증
- 모바일 애플리케이션 구현

## 외부 계약

브라우저 대시보드는 다음 연동 범위를 사용한다.

| 경계 | 용도 |
| --- | --- |
| 대시보드 제공 | 브라우저에서 대시보드 실행 |
| 상태 및 이력 데이터 | 현재 상태, 이력, 임계값과 관리자 요청 및 응답 |
| 실시간 상태 갱신 | 상태와 알림의 변경 내용 수신 |
| 실시간 영상 | 현재 현장 영상 수신 |
| 녹화 영상 | 녹화 구간 조회와 영상 재생 |

정확한 제공 위치, 통신 방식, 주소, 데이터 형식과 오류 형식은 백엔드 및 카메라 역할과
협의하여 확정한다.

## 데이터 계약 경계

프론트엔드는 측정 및 적재 정보, 변화 이력, 운영 이력, 알림, 영상 정보와 관리 설정을
외부 서비스에서 받는다. 데이터 개체와 필드, 단위, 시간 기준, 상태 분류, 측정선별 결과와
통합 결과의 관계는 측정 및 서버 역할과의 계약에서 확정한다. 이 명세는 해당 구조를 먼저
고정하지 않는다.

## 접근 제어

관리 기능에는 인증과 권한 확인을 적용한다. 조회 기능의 접근 정책, 계정 제공 방식, 인증
상태 관리와 요청 보호 방식은 백엔드 계약과 운영 환경에서 확정한다. 프론트엔드는 자격
증명을 소스 코드나 공개 설정에 포함하지 않는다.

## 녹화 영상 조회

프론트엔드는 미디어 서비스가 제공하는 녹화 영상을 조회하고 재생한다. 검색 조건, 제공
메타데이터, 운영 사건과 영상의 연결, 조회 가능 범위와 재생 방식은 미디어 및 서버 역할과의
계약에서 확정한다. 프론트엔드는 녹화 구간을 생성하거나 영상 보존 정책을 결정하지 않는다.

## 초기 개발과 검증

백엔드와 미디어 서비스의 실제 계약이 확정되기 전에는 공개 가능한 합성 데이터와 시험 영상을 사용하여 화면 구성과 사용자 흐름을 확인한다. 이 데이터는 프론트엔드 동작 확인을 위한 것이며 측정 로직의 시뮬레이션 검증에는 사용하지 않는다.

실제 외부 서비스 연동과 검증 방법은 계약 확정 뒤 구현 과정에서 결정하고 저장소의 구현
문서에 기록한다.

## 실행 제약

- 관리자용 브라우저에서 실행
- 일반 인터넷에 직접 공개하지 않는 네트워크 접근 제어
- 공장 내부망, Virtual Private Network (VPN) 또는 이에 준하는 허용된 네트워크에서 조회 화면 접근
- 관리 기능과 설정 변경에 인증 및 권한 확인 적용
- 자격 증명, 사설 주소, 현장 사진, 운영 데이터와 외부 제공 원본의 저장소 포함 금지

## 1차 화면 골격 구현

첫 구현은 실제 외부 서비스 연동 전에 브라우저에서 정보 구조와 사용자 흐름을 확인하는
목적으로 진행한다.

- 현재 모니터링, 변화 및 운영 이력, 녹화 영상과 관리 기능의 정보 구조
- 주요 사용자 흐름과 기능 간 이동
- 핵심 정보의 예제 데이터 표시
- 로딩, 데이터 없음, 오류와 연결 끊김 상태의 기본 표시
- 확정된 대상 브라우저 환경의 렌더링 확인

외부 서비스 연동 범위, 내부 구조, 개발 대역과 구현 순서는 구현 과정에서 결정한다.

## 구현 기술 선호

다음 기술은 전체 프로젝트의 기술 결정이나 모든 Repository에 적용하는 규칙이 아니라
프론트엔드 담당자가 이 Repository의 초기 구현에 제시한 선호다.

| 영역 | 선호 기술 |
| --- | --- |
| UI 구현 | React |
| 구현 언어 | TypeScript |
| 개발 및 빌드 도구 | Vite |
| 스타일 구성 | CSS Modules와 공통 CSS |

구현 담당자는 이 구성을 우선 검토하되 목적, 외부 계약, 실행 제약, 유지보수성 또는 검증
결과에 더 적합한 선택이 있으면 변경을 제안할 수 있다. 실제로 채택한 기술과 버전, 변경
근거와 내부 설계는 `docs/implementation.md`에 기록한다.

## 완료 방향

- 관리자가 브라우저에서 측정 및 적재 정보, 마지막 측정 시각, 변화 추이, 예상 포화 시점, 알림, 실시간 영상과 녹화 영상을 확인할 수 있는 대시보드
- 관리자가 인증 후 수거 임계율과 프로젝트에서 확정한 운영 설정을 관리할 수 있는 기능
- 백엔드와 미디어 서비스의 실제 계약이 확정되면 각 경계를 통해 연동할 수 있는 구조
- 확정된 관리자용 브라우저 환경에서 주요 정보와 관리 기능을 사용할 수 있는 화면

단계별 완료 조건과 세부 검증 절차는 구현 진행에 맞춰 저장소의 구현 문서와 작업 단위에서 구체화한다.
