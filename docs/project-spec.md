## 상위 컨텍스트

스크랩 모니터링 시스템은 LiDAR 2대, 고정 USB 웹캠, 라즈베리파이 엣지 장비, 모니터링 서버와 관리자 브라우저로 구성한다. 엣지 장비는 LiDAR 데이터를 변환하고 높이를 산출하며 카메라 영상을 서버로 전달한다. 모니터링 서버는 상태 데이터, 이력, 알림, 실시간 영상과 녹화 영상을 관리자 브라우저에 제공한다.

이 저장소는 관리자 브라우저에서 실행되는 대시보드 클라이언트를 구현한다. 센서 원본 데이터 처리, 높이 산출, 서버 영속화와 미디어 서버 구현은 다른 개발 저장소의 책임이다.

현재 단계에서는 실제 장비를 이용한 입출력과 네트워크 흐름 확인을 우선한다. 측정 로직의 시뮬레이션 검증은 현재 구현 범위에 포함하지 않는다.

## 목적

공장 관리자가 브라우저에서 스크랩 적재 상태를 확인하고 수거 판단에 필요한 정보를 사용할 수 있는 대시보드를 제공한다.

## 화면 구성

브라우저 클라이언트는 현황, 이력, 녹화 영상과 관리자까지 4개 상위 화면으로 구성한다.

데스크톱 브라우저를 주 사용 환경으로 하고, 전체 화면은 내비게이션 영역과 중앙 콘텐츠 영역으로 구성한다. 첫 화면 골격에서는 좌측 내비게이션을 사용하되, 정확한 너비, 카드 배치, 영상과 그래프 비율, 색상과 간격은 실제 React 화면을 브라우저에서 확인하며 조정한다.

| 화면 | 경로 | 접근 | 주요 내용 |
| --- | --- | --- | --- |
| 현황 | `/` | 로그인 없음 | 적재 상태, 적재율 게이지, 수거 임계율, 실시간 영상, 최근 추이, 활성 알림, 측정 상태와 장비 상태 |
| 이력 | `/history` | 로그인 없음 | 기간별 적재 추이, 수거 이력, 알림 이력, 측정 및 장비 오류 이력 |
| 녹화 영상 | `/recordings` | 로그인 없음 | 녹화 구간 검색, 사건 관련 구간 구분과 영상 재생 |
| 관리자 | `/admin` | 관리자 로그인 | 임계율 설정, 기본값 복원, 자동 알림 설정, 수거업체 알림 대상 관리, 설정 변경 및 관리자 작업 이력 |

현황 화면은 적재 공간 하나의 대표 적재율과 적재 상태를 우선하여 표시한다. 적재 상태는 서버가 제공하는 정상, 수거 필요, 수거 진행과 판정 불가 중 하나다. 판정 불가는 측정 문제로 대표 적재 상태를 제공할 수 없는 경우이며 구체적인 원인은 별도의 측정 상태와 장비 상태에서 표시한다. LiDAR 2대의 개별 거리, 원시 측정값과 내부 계산 과정은 일반 화면에 표시하지 않는다. 적재율 게이지에는 현재 적재율과 수거 임계율을 함께 표시하고 각 상태는 색상 외의 문구로도 구분한다. 수거 진행 상태는 서버가 해당 상태를 판정하여 제공할 때만 표시한다.

활성 알림은 아직 해소되지 않았거나 관리자 확인이 필요한 현재 항목이다. 수거 임계 도달, 측정 오류, 장비 오류와 외부 알림 전송 실패 등을 포함하며 서버가 제공한 항목만 표시한다. 해소된 항목은 현황 화면에서 제외하고 이력 화면에 남긴다.

이력 화면의 적재 추이에는 수거 임계 도달, 알림, 수거와 측정 불가 구간을 같은 시간축에서 확인할 수 있게 표시한다. 측정 및 장비 오류 이력은 발생 시각, 지속 시간, 복구 상태와 영향을 받은 기능을 제공하며 개발자용 원시 로그는 표시하지 않는다.

- React 기반 브라우저 애플리케이션
- Vite 기반 개발 환경과 배포용 정적 빌드
- 서버 데이터, 실시간 상태, 실시간 영상과 녹화 영상 연동 경계
- 합성 데이터 기반 화면 검증 환경

## 외부 계약

브라우저 클라이언트는 다음 5개 경계를 사용한다.

| 경계 | 용도 |
| --- | --- |
| HTTP static assets | 브라우저가 HTML, JavaScript와 CSS 로드 |
| HTTP JSON | 현재 상태, 이력, 임계값과 일반 요청 및 응답 |
| WebSocket | 실시간 상태와 알림 갱신 |
| Web Real-Time Communication (WebRTC) | 실시간 영상 수신 |
| HTTP recorded media | 녹화 영상 조회 |

브라우저는 정적 파일을 로드한 뒤 브라우저에서 실행되는 React 코드가 데이터와 영상을 요청한다. 조회 기능은 애플리케이션 로그인 없이 제공하고, 임계값, 자동 알림과 수거업체 알림 대상 설정에는 관리자 인증을 요구한다. 정확한 호스팅 위치, 주소, 메시지 형식과 오류 형식은 백엔드 및 카메라 역할과 협의하여 확정한다. 프론트엔드는 각 데이터 및 영상 경계를 교체 가능한 클라이언트 모듈로 분리하고, 계약 확정 전에는 합성 데이터와 테스트 대역으로 화면을 검증한다.

## 화면 데이터 요구사항

프론트엔드는 다음 6개 데이터 묶음을 사용한다. 정확한 API 주소, 필드명과 전송 형식은 역할 간 계약에서 확정하되 각 묶음의 의미는 유지한다.

| 데이터 묶음 | 필수 정보 |
| --- | --- |
| 현재 현황 | 대표 적재율, 수거 임계율, 적재 상태, 측정 상태, 장비 상태, 활성 알림 |
| 적재 추이 | 측정 시각, 대표 적재율, 측정 유효 여부 |
| 운영 이력 | 이력 종류, 시작 시각, 종료 시각, 진행 상태, 화면용 설명 |
| 녹화 영상 | 녹화 식별자, 시작 시각, 종료 시각, 생성 사유, 재생 가능 여부, 재생 주소 |
| 관리자 설정 | 현재 임계율, 기본 임계율, 자동 알림 사용 여부, 수거업체 알림 대상 |
| 관리자 작업 이력 | 관리자 식별자, 작업 종류, 변경 시각, 변경 전 값, 변경 후 값 |

운영 이력은 수거 임계 도달, 외부 알림 전송, 수거 진행, 수거 완료, 측정 오류, 장비 오류와 복구를 포함한다. 프론트엔드는 서버가 제공한 판정 결과를 표시하며 적재율, 수거 상태와 오류 상태를 다시 계산하지 않는다.

## 관리자 인증

관리자 인증은 사전 생성된 개별 계정과 서버 측 세션을 사용한다. 브라우저는 세션 식별자만 `HttpOnly` 쿠키로 보관하며 사용자 비밀번호나 장기 인증 토큰을 브라우저 저장소에 보관하지 않는다.

상태 변경 요청에는 세션 기반 인증과 Cross-Site Request Forgery (CSRF) 방어를 적용한다. 정확한 쿠키 속성, 세션 만료 시간과 요청 방식은 백엔드 계약과 운영 환경에 맞춰 구현 과정에서 확정한다. 로그아웃하거나 세션이 만료되어도 로그인 없는 조회 화면은 유지하며 관리자 기능만 잠근다.

## 녹화 영상 조회

녹화 영상 화면은 서버가 제공하는 녹화 구간만 조회하고 재생한다. 첫 진입 시 최근 24시간을 조회 조건으로 사용하며, 실제로 조회 가능한 시작 시각과 종료 시각은 서버 응답을 따른다. 조회 결과가 없거나 일부 시간대의 영상이 없으면 해당 상태를 화면에 구분하여 표시한다.

서버는 각 녹화 구간의 식별자, 시작 시각, 종료 시각, 생성 사유, 재생 가능 여부와 재생 주소를 제공한다. 임계값 도달이나 수거와 연관된 녹화 구간은 일반 녹화와 구분하여 표시한다. 프론트엔드는 임계값 도달 시각, 수거 시작과 수거 완료를 판정하거나 녹화 구간을 생성하지 않는다.

영상의 실제 보존 기간, 연속 녹화 방식, 사건 전후 구간 생성 규칙과 삭제 정책은 미디어 및 서버 역할에서 확정한다. 프론트엔드는 보존 기간을 고정값으로 가정하지 않고 서버가 제공하는 조회 가능 범위를 사용한다.

## 초기 개발과 검증

백엔드와 미디어 서비스의 실제 계약이 확정되기 전에는 공개 가능한 합성 데이터와 시험 영상을 사용하여 화면 구성과 사용자 흐름을 확인한다. 이 데이터는 프론트엔드 동작 확인을 위한 것이며 측정 로직의 시뮬레이션 검증에는 사용하지 않는다.

외부 연결은 화면 구성과 분리하여 실제 계약이 확정되면 연결할 수 있게 한다. 구체적인 개발 대역, 테스트 도구와 검증 절차는 구현 과정에서 결정하고 저장소의 구현 문서에 기록한다.

## 실행 제약

- 최신 데스크톱, 태블릿 및 모바일 브라우저
- 정적 파일로 생성 가능한 배포 빌드
- 일반 인터넷에 직접 공개하지 않는 네트워크 접근 제어
- 공장 내부망, Virtual Private Network (VPN) 또는 이에 준하는 허용된 네트워크에서 조회 화면 접근
- 관리자 화면과 설정 변경에 애플리케이션 인증 적용
- 자격 증명, 사설 주소, 현장 사진, 운영 데이터와 외부 제공 원본의 저장소 포함 금지

## 반응형 화면 기준

화면 구현은 데스크톱 브라우저를 기준으로 진행한다. 화면 하나의 기본 기능이 완성되면 태블릿과 모바일 브라우저 크기에서 동일한 화면을 확인한다. 모바일 전용 화면은 만들지 않고, 내비게이션 접기, 카드의 세로 배치, 영상과 그래프의 너비 조정으로 대응한다.

페이지 전체에 의도하지 않은 가로 스크롤이 발생하지 않아야 한다. 표와 같이 넓은 내용을 유지해야 하는 구성 요소는 해당 영역 안에서만 가로 스크롤을 허용한다.

## 1차 화면 골격 구현

첫 구현은 실제 서버 연동 전에 브라우저에서 전체 구조와 화면별 정보 우선순위를 확인하는 목적으로 구현한다.

- 공통 레이아웃과 좌측 내비게이션
- 현황, 이력, 녹화 영상과 관리자 경로
- 화면별 핵심 정보의 정적 또는 합성 데이터 표시
- 로딩, 데이터 없음, 오류와 연결 끊김 상태의 기본 표시
- 데스크톱, 태블릿과 모바일 브라우저 렌더링 확인

1차 화면 골격에서는 실제 HTTP, WebSocket, WebRTC, 관리자 인증과 녹화 영상 서버를 연결하지 않는다. 구체적인 컴포넌트 구조, 개발 대역, 외부 연결 방식과 구현 순서는 구현 과정에서 결정한다.

## 완료 방향

- 관리자가 브라우저에서 현재 적재 상태, 변화 추이, 활성 알림, 실시간 영상과 녹화 영상을 확인할 수 있는 대시보드
- 관리자가 인증 후 수거 임계율, 자동 알림 사용 여부와 수거업체 알림 대상을 관리하고 관리자 작업 이력을 확인할 수 있는 기능

- 데스크톱 브라우저를 우선으로 하고 태블릿과 모바일 브라우저에서도 주요 정보와 조작 기능을 사용할 수 있는 화면
